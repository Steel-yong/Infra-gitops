무엇이 바뀌나 — 기존 결정 vs 재검증 결론

기존 보고서 결정 폐기 권고

  1. 주력: 플레이어 아이콘 앵커 + 미니맵 오도메트리(상시).
  2. fallback: 자기장 원 ruler + locked circle 재앵커.
  3. 보정: 결정론 지도 앵커(라벨·격자·해안선).

약점: 플레이어가 줌 프레임 밖이면 주력 붕괴. scale 단일 소스. 측정 없이 3계층. 상시 로컬라이제이션은 과설계.

재검증 결론 채택 권고

  1. 프레이밍: 상시 → 새 존 공지 시 lock window 열고 윈도우 내 multi-frame 후보를 합의(N-of-M)로 commit.
  2. phase별 주력: 후반은 미니맵 경계기하, 전반은 원 ruler(아래 표).
  3. scale: 줌레벨 분류가 1순위, 원 반경 단독 확정 금지(교차검증).
  4. 플레이어 앵커는 "보이면 재앵커"로 강등, 오도메트리는 제거.

빌드 전 측정 게이트 — 0단계 (가장 싼 것부터)

  1. 미니맵 중심 = 플레이어 위치인지 확인. (녹화 1편으로 즉시)
  2. 미니맵 회전 설정·실제 회전 빈도 확인.
  3. 후반 줌 글랜스에 플레이어 아이콘 들어오는 프레임 비율 측정. (R3-2 검증 — 플레이어 앵커 가치 판정)
  4. 후반 미니맵에 자기장 경계 호 보이는 비율 + arc span·곡률 측정. (F 주력 승격 근거)
  5. 미니맵 광학흐름 drift(핑·팀원·연막·차량) 측정. (오도메트리 제거 검증)
  6. 원 반경 scale ↔ 줌레벨/격자/미니맵/초기 전체맵 scale 교차검증 가능성.

보류 유지

· factor graph — 첫 빌드 아님. 측정·앵커가 생긴 뒤 관측을 confidence로 합치는 얇은 scorer로만.
· ML 위치추론 — 보류 유지. deterministic 앵커로 실제 줌 crop auto-label이 쌓인 뒤 애매 crop ranking 보조로 재평가.
· 미니맵 오도메트리 — MVP core 제거. "윈도우 lock 실패 시 임시 holdover" 실험 항목으로만.
최종 권고. 기존 보고서의 3계층(플레이어 앵커 주력·상시)을 폐기하고, ① 측정 게이트 6개 선행 → ② 공지 윈도우 multi-frame lock 프레임워크 → ③ phase 구간별 주력(후반 F / 전반 ruler) → ④ scale 교차검증으로 재설계한다. 플레이어 아이콘은 보조 재앵커, factor graph·ML·오도메트리는 보류. 가장 싼 측정 1·3·4번을 녹화 한두 편으로 먼저 돌려 F와 플레이어 앵커의 실제 가치를 데이터로 확정한 뒤 빌드 순서를 잠근다.
