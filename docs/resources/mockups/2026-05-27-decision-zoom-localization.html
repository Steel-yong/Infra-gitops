핵심 원리. 자기장 원은 OCR 페이즈로 반경을 아니까 줌 배율(scale)을 정확히 확정한다. 그러나 원 하나로는 절대 위치(translation)를 못 정한다 → 위치는 아래 중 하나로 채운다: ① 이전 앵커 / ② 해안·격자·라벨 / ③ 프레임 추적 / ④ 두 원(현재+다음).

6계열 비교

계열원리위치를 채우는 것강점약점난이도가능성
A. 원 ruler + 앵커1순위·지금
(사용자 안)		 줌 화면 흰 원 검출 → 페이즈 반경으로 scale 확정 → 이전 전체맵 앵커(같은 원의 절대중심)로 즉시 affine 복원. ① 앵커 가장 단순·정확. 특징점 0. 원검출 PoC 검증(25~39%). 전체맵 1회 락(앵커)이 전제. 앵커 없으면 불가. 하 상
B. 원 ruler + 두 원보강 현재+다음 원 2개의 반경·상대위치로 translation 후보를 크게 줄임. ④ 두 원 앵커 없이도 위치 제약 강화. 두 원이 화면에 같이 보여야. 중 상
C. scale 고정 + 맵구조 매칭콜드스타트 폴백 반경으로 scale 고정 후, 해안선·물가·edge·도로를 chamfer/NCC로 전역 매칭해 translation 탐색. ② 해안·edge 앵커 없을 때 강함. AKAZE보다 PUBG맵에 맞음(해안 유니크). 내륙(물 없음)·색차 보정 필요. 중~상 상
D. 격자선·라벨 OCR보강 격자(A~H/1~8) 선·라벨 또는 도시명 OCR → 절대 cell/좌표 앵커. ② 격자·라벨 보이면 절대위치 바로. PUB-34에서 격자OCR 경험 있음. 강한 줌·설정에 따라 안 보일 수 있음. 중 중
E. 프레임간 오도메트리연속성 초기 앵커 후 optical flow/위상상관으로 viewport 이동량 누적. (E 유저위치와 같은 메커니즘.) ③ 추적 연속 사용 UX에 강함. 한 번 잡으면 유지. 드리프트 → 주기적 재앵커 필요. 중 상
F. ML 위치회귀최후 폴백 CNN이 크롭→좌표 학습(place recognition). 학습된 모델 가장 강건 가능. 데이터·GPU·서빙(Phase 6). 무거움. 상 중

추천 — 단계적으로 쌓기

  1. A부터 (사용자 안) — 전체맵 1페이즈 앵커 + 원 ruler. 가장 단순하고 우리 흐름(1페는 안 줌으로 검출)에 정확히 맞음. 이걸 먼저 구현·라이브 검증.
  2. B 보강 — 줌에 다음 원도 보이면 두 원으로 위치 제약(앵커 정확도 ↑).
  3. C 폴백 — 앵커가 아직 없을 때(콜드스타트) 해안/edge 매칭으로 위치 보충.
  4. E 연속성 — 한 번 잡은 뒤 프레임 추적으로 유지, 신뢰도 하락 시 A로 재앵커.
