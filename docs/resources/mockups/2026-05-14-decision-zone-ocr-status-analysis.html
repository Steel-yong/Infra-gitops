현재 상태 분석 — 자기장 + OCR

2026-05-14 · capture-service 로그 + docker 상태 기반 / 추측 아닌 실측

1. 자기장 검출 — 측정된 동작

증상: 매 프레임 검출 시도 → 전부 거부됨

capture-service 로그가 1초마다 같은 패턴 반복.

전체맵 열림 감지 — 자기장 원 추출 시작 잔차 초과: avg=161.1px (허용 137.1px) 자기장 원 추출 실패 전체맵 열림 감지 — 자기장 원 추출 시작 잔차 초과: avg=153.1px (허용 134.9px) 자기장 원 추출 실패 ... (계속 반복)

해석

① 청록 검출 전체맵 열림 = TRUE (3% 임계 통과)
② 엣지 픽셀 수집 50개 이상 통과 (개수는 충분)
③ Kasa 원 피팅 중심+반경 계산됨
④ 잔차 검증 평균 잔차 152~163px (허용 134~140px) → REJECT

잔차가 반경의 15% 초과 = 점들이 진짜 원을 안 이룸.

가능한 원인 (확인 필요)

  • 가설 A: 사용자가 PUBG 전체맵을 안 열고 있음 (Tab 키 안 누름). 그래서 in-game 화면의 노이즈 픽셀만 들어옴.
  • 가설 B: 청록 임계값 3%가 너무 관대 — 일반 in-game 하늘/물도 통과해서 잘못 "맵 열림" 판단.
  • 가설 C: 사용자가 정말 전체맵 열었는데, JPEG 압축으로 얇은 자기장 외곽선이 손상되어 픽셀 분포가 흩어짐.
  • 가설 D: 자기장 외곽선이 매우 얇아서 4픽셀 간격 샘플링이 외곽선을 거의 못 잡음.

2. OCR 타이머 — 알 수 없음

증상: 브라우저 사이드 동작 미확인

OCR은 사용자 브라우저에서 실행됨. 서버 로그에 안 잡힘.

가능한 상태:

패널 표시의미대응
화면공유 시작 후...isCapturing=false (공유 시작 안 함)"공유 시작" 클릭
OCR 엔진 다운로드 중...Tesseract.js 다운로드 진행30초~1분 대기
OCR 실패: [에러]Worker 초기화 실패에러 메시지 보고
--:--OCR 동작 중이지만 인식 못 함좌표 어긋남, 또는 타이머 안 보임
1:38 같은 값정상 동작완료

3. 근본 해결 방향

지금 같은 방식의 한계

흰 픽셀 → Kasa 원 피팅 방식의 본질적 문제:

  • 지명 텍스트, 도로, 그리드선, UI도 흰 픽셀 → 노이즈
  • 엣지 필터로 일부 거름 → 자기장 외곽선도 같이 거름 (얇아서)
  • 잔차 임계로 노이즈 거름 → 실제 자기장도 노이즈와 섞여 거름
  • "모든 흰 픽셀을 하나의 원으로 피팅"은 PUBG에선 작동 어려움

제안: 페이즈 기반 검출 (이전에 합의했던 안)

핵심 전환: 반경은 페이즈에서 + 중심만 검출

  • 페이즈 1 → 반경 0.1875 (공식 데이터)
  • 페이즈 2 → 0.1375, 페이즈 3 → 0.0825, ...
  • 중심점만 찾기 — 흰 픽셀들의 무게중심 또는 클러스터 중심
  • 전체 원이 아닌 점을 찾는 거라 훨씬 안정적

필요한 것: 현재 페이즈 번호를 알아야 함 → OCR 타이머가 동작해야 함.

의존성 체인

① OCR 동작 확인먼저 해야 할 것
② 페이즈 추정 로직OCR + 누적 시간
③ 자기장 중심 검출알고리즘 재작성
④ 페이즈 반경 사용DB에서 조회
