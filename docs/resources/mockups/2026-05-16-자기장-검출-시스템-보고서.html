1. 한 줄 요약

화면공유 frame에서 청록 바다로 PUBG 디스크 영역을 자르고, 그 안의 흰 픽셀(자기장 외곽선) 또는 파란/비파란 전환 픽셀(외곽 경계)로 RANSAC을 돌려 PUBG 페이즈별 기대 반경(공식 값)과 매칭되는 원을 찾습니다. Cold start는 페이즈 1~4 후보로 제한하고, 페이즈 5~8은 hintPhase ±1로만 진입합니다.

2. 자기장 찾는 방식 (핵심 플로우)

1
화면공유 frame 도착 (500ms 주기, JPEG base64 인코딩)
→ capture.gateway WebSocket으로 수신
2
PUBG 디스크 영역 찾기 (map-detection.service)
→ 청록 바다 픽셀의 bounding box로 정사각형 잘라냄
→ 보통 1920×1080 화면이면 left=420, top=0, 1080×1080
3
흰 픽셀 + 파란 픽셀 측정 (circle.service)
→ 흰: R ≥ 240 & G ≥ 240 & B ≥ 240
→ 파랑: B > R+30 & B > G+30 & B > 90 (바다 제외 조건 포함)
4
모드 분기
파란 비율 ≥ 5% → 자기장 줄어드는 중 → blue-edge 모드 (실패 시 white 폴백)
파란 비율 < 5% → 자기장 형성 직후 또는 wait → white 모드
※ 페이즈 1은 줄어들면서 파란이 0% → 천천히 누적되는 특수 상태. 5% 근처에서 모드 진동 가능하나 폴백으로 검출 유지.
5
페이즈 후보 결정
Cold start (hintPhase 없음): [1, 2, 3, 4]만 — 작은 페이즈(5~8) 잡음 매칭 차단
hintPhase 있음: [hintPhase-1, hintPhase, hintPhase+1] ±1 확장 → 페이즈 5~8 진입 가능
6
RANSAC 원 피팅 (2000번 반복)
매번:
① 무작위 3점 뽑아 원 1개 결정
② 그 원의 반경이 페이즈 후보 기대값 ±12% 안인지 검사
③ 들어가면 외곽선 ±2px 이내 점 개수 = score 계산
→ 가장 score 높은 원 채택
7
임계값 검증
score < minScoreForPhase(phase) (이론 max의 40%, floor 80) → null 반환
통과 → { x, y, r, phase } 반환 (정규화 0~1)
8
frontend가 결과 받음
→ useLockedCircle이 락에 채택 (페이즈 전환 시 즉시 갱신)
→ CircleOverlay가 Leaflet 위에 그림

PUBG 공식 페이즈 반경 + Score 임계값

Score = 외곽선 ±2px 이내 inlier 점 개수. 이론 max ≈ 2π × r × 두께, 페이즈 1~2는 maxPts=3000 cap 적용.
Threshold = 기존 보수적 값 유지 (baseScore=800 × 반경비례, floor 200). 페이즈 5~8 잡음 차단은 coldStartPhases [1,2,3,4]로 1차 방어.
※ 40% 균일 그라디언트(1200/728/402/221) 시도했으나 외곽선 두께 1px 환경에서 진짜 자기장도 못 넘을 위험으로 되돌림. 실측 후 재조정 예정.

3. 색깔 신호의 의미

흰 픽셀 (검출 대상 ✓)

  • 자기장 외곽선이 흰 색 (R/G/B 모두 ≥ 240)
  • RANSAC에 입력되는 점
  • 임계값 240 강화 후: 그리드 라인(약 220) 제외, 자기장 외곽선만 남음

파란 픽셀 (모드 분기 신호 + blue-edge RANSAC ✓)

  • 자기장 외부 위험 구역의 진한 파란색
  • 비율 측정 + 파란/비파란 전환 픽셀로 외곽선 추출
  • 바다 청록색은 g < r + 25 조건으로 제외
  • 페이즈 1은 0%에서 시작 → 천천히 누적 (다른 페이즈는 형성 직후 이미 채워져 있음)

청록 바다 (디스크 영역 찾기용)

  • RGB로 G ≈ B > R 인 어두운 청록
  • map-detection이 이걸로 PUBG 디스크 영역 bounding box 잡음
  • circle.service의 isBluePixel은 청록 바다 제외 (다른 조건)

노란 점 (정밀 중심 보정)

  • 자기장 안 노란 마커 (R≥200, G≥180, B≤100)
  • blue-edge 모드(페이즈 2~8)에서만 적용
  • 가장 큰 노란 cluster의 무게중심으로 원 중심 미세 보정

4. 게임 상태별 검출 결과

게임 상태화면에 보이는 것검출 결과비고
매치 시작 후 페이즈 1 wait (120초) 디스크 외곽선 + 빨간 미리보기 원만 미검출 흰 자기장 원 자체가 없음 — 검출 안 되는 게 정상
페이즈 1 자기장 형성 후 줄어드는 중 큰 흰 원 + 파란 외부 페이즈 1 blue-edge 또는 white RANSAC
페이즈 1 줄어드는 중 + 페이즈 2 미리보기 흰 원 + 작은 빨간 원 페이즈 1 빨강 무시, 흰 원만 잡음
페이즈 2 자기장 형성 + 줄어드는 중 작은 흰 원 + 파란 외부 페이즈 2 락 자동 페이즈 2로 갱신
페이즈 3~8 진행 점점 작아지는 흰 원 페이즈 N 페이즈별 반경 매칭
화면이 게임 외 다른 창 청록 픽셀 적음 미검출 map-detection이 디스크 못 찾음

6. 잘못 잡히는 케이스 (남은 문제)

증상

페이즈 1 wait 동안 (자기장 흰 원 없음), 또는 자기장 작은 페이즈에서 알고리즘이 잡음 흰 픽셀(UI 텍스트, 작은 마커, 지형 흰 선) 3개에 우연히 페이즈 N 반경 ±12% 안 들어가는 원을 매칭해서 가짜 검출 발생.

원인

  • 작은 페이즈일수록 r이 작아 잡음으로도 우연 매칭 쉬움
  • 화면 어디든 흰 픽셀이 100여 개씩 있음 (UI, 그리드 일부)
  • 현재는 페이즈 후보가 cold start 시 1~8 전체 → 가장 작은 페이즈 4~8이 잡음에 매칭됨

현재 대응

  • score floor 200 → score 100~150 잡음 매칭은 차단됨
  • 그러나 가끔 score 200~300으로 통과하는 가짜 검출이 남아 있음

7. 적용된 개선 (2026-05-16)

7.1 빨간 픽셀 관련 서술 제거

이전 보고서에 "빨간 원 = 다음 페이즈 미리보기"라는 검증되지 않은 해석이 들어있었음. 빨간 픽셀은 이미 흰 임계값과 파란 조건에서 자동 제외되므로 검출 알고리즘에 영향 없음 → 보고서에서 관련 설명 일체 삭제.

7.2 Cold start 페이즈 후보를 [1, 2, 3, 4]로 제한

변경: circle.service.ts의 allPhasesForBlueEdge = [1,...,8] → coldStartPhases = [1, 2, 3, 4].

이유: 화면공유 시작 타이밍은 90% 이상 페이즈 1~4. 페이즈 7~8의 기대 반경(5.5px, 2.7px)은 너무 작아 화면 잡음 흰 픽셀에 우연 매칭 쉬움. 후보에서 빼면 RANSAC이 작은 원을 만들지 않음.

확장: hintPhase가 잡힌 후 ±1로 페이즈 5~8까지 자연스럽게 진입.

트레이드오프: 화면공유 도중 페이즈 7~8에서 첫 시작하는 케이스(1% 미만) 미검출. 허용.

7.3 Score threshold — 보수적 값 유지 (40% 그라디언트 시도 후 되돌림)

최종: 기존 공식 그대로. baseScore=800 × 반경비례, floor 200.

시도 후 되돌린 이유: 40% 균일 그라디언트(1200/728/402/221)는 외곽선 두께가 1px(안티에일리어싱 환경)인 사용자에서 진짜 자기장도 threshold 못 넘을 위험.

  • 두께 1px → 외곽선 픽셀 ~1659개 → 1200/1659 = 72% inlier 필요. 너무 빡빡.
  • 두께 2px 환경에서만 안전. 사용자 환경 가변성 큼.
  • 페이즈 5~8 잡음 차단은 cold start [1,2,3,4]로 이미 1차 방어됨 → score 그라디언트 변경 효과 불필요.

다음: Cold start 단독 효과 실측 후 score 그라디언트 재조정 여부 결정.

function minScoreForPhase(phase: number): number {
  const baseScore = 800;
  const ratio = PUBG_PHASE_RADII[phase - 1] / PUBG_PHASE_RADII[0];
  return Math.max(200, Math.floor(baseScore * ratio));
}

7.4 보류 — "다음 페이즈를 이전 페이즈 자기장 안에서만 찾기"

parentCircle 제약 아이디어는 유효하나, cold start 제한 + score 재조정 효과 측정 후 필요 시 별도 이슈로 진행.

8. 페이즈 OCR — 비활성화 상태 + 재활성화 조건

현재 상태

useOcrTimer.ts:324 PHASE_OCR_ENABLED = false로 비활성화.

OCR 진행 흐름

  1. 1초마다 tick 중 5초 주기마다 페이즈 영역 처리.
  2. 비율 좌표 x=0.940, y=0.700, w=0.050, h=0.040으로 ROI crop (1920×1080 기준 96×43px).
  3. 3× 확대 + 임계값 220 흰 픽셀 검정 반전 전처리.
  4. Tesseract.js whitelist "0123456789:"로 인식.
  5. parsePhaseString이 첫 1~8 단일 숫자 추출.
  6. 같은 숫자 연속 3회 일치 시 currentPhase 갱신, 빈 결과 4회 연속이면 null 리셋.
  7. capture.gateway에 hintPhase로 전달.

실패 요인

원인설명
ROI 좌표 부정확비율이 1917×1198 단일 캡처 기준. 사용자 화면 비율·해상도·UI 스케일이 달라지면 "페이즈 N" 글자에서 빗나감
글자 너무 작음96×43 ROI는 한글 + 숫자 + 안티에일리어싱 다 들어가 3× 확대로도 부족
인접 UI 간섭ROI 빗나가면 미니맵 안 좌표·타이머·맵 인덱스 숫자 잡음 (4/5/6으로 오인식)
Tesseract 약점작은 폰트에서 1↔4↔7, 5↔6, 3↔8 자주 헷갈림

재활성화 조건

  1. 사용자 실제 게임 raw 캡처(PNG) 제공.
  2. "페이즈 N" 글자 정확한 픽셀 좌표 측정.
  3. PHASE_REGION_RATIO 재계산 (timer-ocr-utils.ts).
  4. 디버그용 ROI 박스 시각화 추가 (선택).
  5. PHASE_OCR_ENABLED = true.

OCR 없이도 자기장 검출은 동작: cold start [1,2,3,4] + 세션 추적 lastPhase로 hintPhase 대체.
