4. Overview [00] 디자인 — UX 원칙 3가지

1

F자 패턴 시선 흐름

왼쪽 위 = 가장 중요. 사용자 시선이 자연스럽게 따라가는 F자 패턴에 맞춰 우선순위 배치.

2

색은 의미일 때만

녹/노/빨 = 정상/주의/이상. 장식용 색 금지. 무채색 기본 + 이상 시에만 색.

3

0이면 사라짐

"Pending Pod: 0", "CrashLoop: 0" 같은 평시 패널은 0일 때 회색으로 숨김. 이상 시에만 강조.

8. 액션 — 결정 필요 6가지

① 이 7개 구성 OK?

빼고 싶은 거 / 추가하고 싶은 거 있어? (예: Vault 전용 대시보드, Cilium 메트릭 별도 등)

② Overview의 Row 5 (Loki 로그 통합)

한 화면에 메트릭+로그 같이 보는 패턴. 인지 비용 약간 ↑인데 디버깅 효율 ↑. 넣을까?

③ Folder로 그루핑

"K8s 자원 / 노드&스토리지 / 플랫폼 / 자기관측 / 로그" 5개 folder. 마음에 들어? 다른 분류 원해?

④ 번호 prefix [00]~[11]

Grafana는 알파벳 정렬이라 번호 prefix가 강제 정렬용. OK?

⑤ 내장 대시보드 18개 끄는 방법

kube-prometheus-stack values.yaml에서 grafana.defaultDashboardsEnabled: false로 전부 끄고, 7개 KEEP 대상만 ConfigMap으로 다시 박는 방식 vs 개별 grafana.dashboards 키에서 빼는 방식. 다음에 결정.

⑥ "01~11" 진짜 번호 매김 vs 다른 naming

예: 01-cluster-resources vs K8s · Cluster Resources 이런 식의 raw prefix vs separator. 취향 선택.

✨ 이 6개 결정되면

다음 단계: Overview JSON 작성 → Logs JSON 작성 → 6개 KEEP 대시보드 ConfigMap화 → values.yaml에서 18개 disable → 검증.
