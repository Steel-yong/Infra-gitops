선택지 비교

접근방법장점단점실시간?
A. 미니맵 템플릿매칭추천 1순위 미니맵 크롭을 기준맵에 정규화상관(NCC) 다중스케일로 위치 검색. 미니맵 중심=플레이어. 흰 화살표로 heading. 사용자 승인 "실시간 미니맵" 요구 유지. 특징점 불필요 → 작은 영역에 AKAZE보다 강할 가능성. 미검증(PoC 필요). 바다·설원 등 단조 지형 오정합 위험. 미니맵 회전 시 보정 필요. ✅ 가능
B. 전체맵 화살표 검출보조 M키 전체맵에서 플레이어 흰 화살표 검출. 전체맵은 이미 zone 검출이 좌표계 확보 → 절대좌표 직접. 로컬라이제이션 불필요 → 구현 단순·신뢰도 높음. 전체맵 열 때만 → "실시간" 요구 위반. 마커가 자기장·핑과 겹치면 오검출. ❌ (열 때만)
C. ML 학습폴백 미니맵→위치를 학습 모델로 추론. 단조 지형·회전에 강건 가능. 데이터·학습 비용 큼. 원 계획상 폴백. ✅ 가능(비쌈)

추천

① A를 PoC로 먼저 검증 — 미니맵 크롭 NCC가 기준맵에서 플레이어 중심을 안정적으로 찾는지(스케일·위치 오차 측정).

② 결과 분기 — PoC 통과 → A 구현. 실패 → B(실시간 포기, 전체맵 열 때 내 위치) 또는 C(ML).

③ 하이브리드 가능 — 평소엔 A(실시간), 전체맵 열렸을 땐 B(정확) 병행도 자연스럽습니다.

막힌 점: A의 PoC에는 인게임 미니맵(우하단) 원본 프레임이 필요합니다. 현재 .claude/images엔 풀맵·앱스샷·종료화면뿐이라, 체인 영상에서 1프레임 추출하거나 사용자가 미니맵 스샷 1장을 주셔야 합니다.

결정 후 액션

  • A 선택 → 미니맵 프레임 확보 → NCC PoC(.local/poc_player_template.py) → 통과 시 capture detectPlayer() 구현.
  • B 선택 → 전체맵 화살표 검출기(흰 삼각형 connected-component) → 이미 있는 전체맵 좌표계로 환산.
  • C 선택 → 라벨 데이터 수집 + 모델 — 별도 대형 이슈.

이미 완료(접근 무관): shared.PlayerPosition{x,y,heading} 타입 + SocketEvents.PLAYER_RESULT 이벤트.
