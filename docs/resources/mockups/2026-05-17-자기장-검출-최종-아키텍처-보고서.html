1. 한 줄 요약

폴링 기반 → 이벤트 기반으로 전환. OCR 페이즈 인식을 게이트키퍼로 두고, 페이즈 락과 자기장 락 모두 sticky로 만들었다. 다음 페이즈는 이전 자기장 안에서만 검색. 페이즈 1~4 실 게임 테스트 완료. 사용자 사운드 알람도 적용.

2. 핵심 아키텍처 — 이벤트 기반 OCR 게이트키퍼

이전 (잘못된 방식)

  • 0.5초마다 무조건 RANSAC → CPU 낭비 + 잡음 매칭 가짜 검출.
  • 페이즈 추정이 검출 반경에 의존 → 첫 검출이 잘못되면 페이즈도 잘못 잡힘.
  • 락 자동 해제 15회 미검출 시 → 맵 닫고 파밍하면 락 풀림.

현재 (옳은 방식)

원칙내용
OCR 게이트키퍼화면 "페이즈 N" 글자가 OCR에 잡혀야만 RANSAC 호출. OCR null = 자기장 검출 자체를 안 함
OCR 페이즈 sticky한번 락된 currentPhase는 다른 페이즈가 확정될 때까지 유지. 빈 결과로 절대 null 리셋 안 함
자기장 락 sticky한번 락된 lockedCircle은 자동 해제 안 함. 페이즈 전환 또는 수동 unlock 으로만 해제
parentCircle 제약다음 페이즈 검색은 이전 페이즈 자기장 안에서만. PUBG 룰(페이즈 N+1 ⊂ 페이즈 N) 강제
1초 OCR 폴링페이즈 OCR이 1초마다 발화. 같은 페이즈 2회 연속 = 2초 안에 락

3. 상태 머신

페이즈 OCR이 null ┌──────────────────────┐ ↓ │ ┌──────────────────────┐ │ │ [IDLE / GAME_PREP] │ │ │ OCR null, 락 없음 │ │ │ → RANSAC 호출 안 함 │ │ └──────────┬───────────┘ │ │ 페이즈 OCR이 N 인식 │ │ (1초 × 2회 = 2초) │ ↓ │ ┌──────────────────────┐ │ │ [PHASE_LOCKED] │ │ │ currentPhase = N │ │ │ → capture 호출 시작 │ │ └──────────┬───────────┘ │ │ 자기장 검출 성공 │ ↓ │ ┌──────────────────────┐ │ │ [CIRCLE_LOCKED] │ │ │ lockedCircle 락 │ ───────────┘ │ UI에 원 표시 │ │ ↑ 맵 닫혀도 유지 │ └──────────┬───────────┘ │ 페이즈 OCR이 M (≠ N) 인식 ↓ ┌──────────────────────┐ │ [NEXT_PHASE_LOCKED] │ │ currentPhase = M │ │ parentCircle = 이전 락│ │ → 이전 원 안에서 검색│ └──────────────────────┘

TODO 9.1 맵 확대 상태 자기장 인식

현재 알고리즘은 풀맵(M키, 전체 맵 정사각형)이 화면에 펼쳐진 상태를 전제. 사용자가 마우스 휠로 맵을 확대하면 디스크 영역 청록 bounding box가 작아지거나 사라지고, 자기장 픽셀 좌표도 크게 어긋난다.

해결 방향 후보:

  • 줌 레벨 추정: 청록 픽셀 비율 + 격자선 간격으로 확대 비율 측정 → RANSAC tolerance를 확대 비율 비례로 늘림.
  • 확대 상태 감지 후 OCR 게이트 강화: 풀맵 종횡비/크기 검증 통과해야만 검출 시도.
  • 확대 화면용 별도 모드: 확대 시 자기장 일부만 보이므로 호 fitting (전체 원 못 봐도 일부 호로 추정).

실제 사용 패턴 보고 우선순위 결정.
