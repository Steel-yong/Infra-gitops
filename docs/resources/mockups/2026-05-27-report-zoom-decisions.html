줌 자기장 로컬라이제이션 — 3대 결정사항

보고서 · 2026-05-27 · Claude↔Codex 2라운드 비판 토론 결론 · 기준: 정확도 + 유저 편의성 변수 최소(항상 줌·후반 짧은 글랜스) · 시간/노력 무관

배경. 사용자는 게임 중 전체맵을 무조건 확대해서 본다(안 줌 없음). 후반(4·5페)엔 교전이 많아 맵을 아주 짧게만 보고 자기장은 빠르게 줄어든다. 이미지 특징점 매칭(AKAZE/SIFT)·템플릿 매칭은 게임렌더와 기준맵의 겉모습 차이로 실패. 이 제약에서 "무마찰 + 정확"을 만족하는 방식을 3계층으로 결정함. 관통 원칙: 신뢰도 낮으면 자기장을 확정해 그리지 말고 보류(틀린 안내는 없느니만 못함).

결정 1 · 주력플레이어 아이콘 앵커 + 미니맵 오도메트리

주력 로컬라이저로 채택. 전체맵 글랜스가 짧아도 항상 켜진 미니맵으로 플레이어 절대위치를 계속 추적하고, 글랜스에선 플레이어 아이콘 1개를 앵커로 자기장을 절대좌표화한다.

동작
  1. 1페 전체맵에서 플레이어 절대위치 P_world 확보.
  2. 미니맵 배경 광학흐름으로 P_world 계속 갱신(글랜스 불필요).
  3. 줌 글랜스: 플레이어 아이콘 픽셀 + 자기장 원 검출 → scale=원반경px/페이즈반경 → 자기장절대 = P_world + (원−아이콘)/scale.
근거 / 리스크 대응
  • 무마찰: 미니맵 상시 → 짧은 글랜스 문제 정면 해결. 정확: 아이콘=뚜렷 단일 마커, 겉모습·학습 무관.
  • 아이콘 미가시 → 결정2로 fallback. 오도메트리 드리프트 → confidence + 미니맵 재매칭 + 아이콘 보이면 재앵커.
  • 부수효과: PUB-40(유저 실시간 위치)과 토대 공유 → 두 기능 동시 해결.
상태: 1순위 빌드 예정 (feature/PUB-39-zoom-v2, 순수변환 모듈 8/8 완료)

결정 2 · 보조(결정론 fallback)자기장 원 ruler + locked circle 재앵커

그동안 논의한 "두 원 체인"은 메인에서 fallback으로 강등. 후반 단일 글랜스에 약하고 누적오차가 있어 주력이 될 수 없음. 단순·결정론적이라 보조로 유지.

근거 / 리스크 대응
  • 아는 원이 같이 보일 때만 작동. phase 반경·parent containment를 hard gate, 위반 시 retain.
  • 신뢰도 낮으면 새 좌표 미출력. 플레이어 아이콘(결정1) 가용 시 그쪽 우선.
상태: 순수 변환 모듈 재사용(이미 구현·테스트), 검출부만 보강

결정 3 · 보조(재앵커/보정)결정론적 지도 앵커 매칭 (라벨·격자·해안선·도로)

플레이어 아이콘 미가시 + 미니맵 드리프트 클 때 재앵커·보정 역할. ML 아닌 결정론. scale 고정 후 translation을 지도구조 다채널 점수로 탐색, 1·2등 margin 게이트.

근거 / 리스크 대응
  • 학습 불필요, 실패 사람이 해석 가능. 평야·반복지형 약함 → 다채널 합산 + margin + hard gate(parent·phase·odometry 범위).
  • 구현량 큼 → 결정1의 드리프트 재앵커, 결정2의 fallback으로만 우선 부착.
상태: 후순위 (결정1·2 동작 후 보강)
보류 (이번 결정에서 제외).
· Factor graph 융합 — 위 3계층 앵커가 생긴 뒤 확률적으로 합쳐 "좌표+신뢰도+대체후보"를 내는 최종 통합 레이어. 첫 빌드 대상 아님.
· ML 위치추론 — "줌crop+정답좌표" 데이터 부재 + 합성crop 도메인갭. 위 결정론 앵커로 실제 줌을 auto-label해 데이터가 쌓이면 애매한 crop의 후보 ranking 보조로 재평가.
다음 액션. 결정1(플레이어 아이콘 + 미니맵 오도메트리)부터 빌드 → 순수 모듈 유닛 → capture/프론트 배선 → 라이브 검증 후 머지. 결정2·3은 fallback으로 단계적 부착. 라이브에서 후반 끊김 빈도 측정 후 보류 항목(ML 등) 재평가.
