줌 자기장 로컬라이제이션 — 최종 Top 3

Claude↔Codex 2라운드 비판 토론 결과 · 기준: 정확도 + 유저 편의성 변수 최소(항상 줌·후반 짧은 글랜스) · 시간/노력 무관

핵심 전환. "두 원을 한 프레임에"(체인)는 후반 짧은 글랜스에서 자주 깨지고 누적오차가 생겨 메인이 될 수 없다 → fallback. 메인은 항상 켜진 미니맵으로 플레이어 위치를 계속 추적하고, 전체맵 글랜스에선 플레이어 아이콘 하나를 앵커로 쓰는 것. 글랜스가 짧아도 미니맵이 끊김을 메운다.

1순위 · 먼저 빌드플레이어 아이콘 앵커 + 미니맵 오도메트리

파이프라인
  1. 1페(전체맵)에서 플레이어 절대위치 P_world 확보.
  2. 이후 항상 켜진 미니맵을 crop → 배경 이동량(optical flow) 누적해 P_world 계속 갱신(글랜스 불필요).
  3. 전체맵 줌 글랜스 들어오면 플레이어 아이콘 픽셀 P_px + 자기장 원 C_px,R_px 검출.
  4. scale = R_px / 페이즈반경, C_world = P_world + (C_px − P_px)/scale.
무마찰: 미니맵 항상 켜짐(글랜스 짧아도 됨), 평소대로 플레이. 정확: 플레이어 아이콘=뚜렷한 단일 마커, 겉모습 무관, ML/학습 불필요.
실패 + 메움
  • 아이콘 안 보이는 글랜스 → 2순위로 fallback.
  • 미니맵 오도메트리 드리프트 → confidence 점수(추적점·flow 일관성) + 미니맵 주기적 재매칭 + 아이콘 보이면 즉시 재앵커.
  • 초기 P_world 오류 전파 → 결과가 parent containment·phase 규칙 위반하면 폐기.

2순위 · 결정론 fallback자기장 원 ruler + locked circle 재앵커

파이프라인
  1. 전체맵 정상검출 때 현재/이전 자기장 절대좌표 Z_known 저장.
  2. 줌 글랜스에서 흰 원 arc → RANSAC 픽셀원 Z_px.
  3. 아는 원이 같이 보이면 Z_px ↔ Z_known + 페이즈반경 scale → 변환 → 다음 자기장 복원.
단순·결정론적, 원은 뚜렷, ML/플레이어 상태 불필요. 단점: 아는 원이 같이 보여야 함(새 원만 보이면 미확정).
실패 + 메움
  • phase 반경·parent containment를 hard gate. 위반 시 retain(기존 유지).
  • confidence 낮으면 새 좌표 안 내보냄. 플레이어 아이콘(1순위) 보이면 그쪽 우선.

3순위 · 재앵커/보정결정론적 지도 앵커 매칭 (라벨·격자·해안선·도로 다채널)

파이프라인
  1. 기준맵에서 라벨위치·격자·해안선·도로·건물밀도 채널 사전생성.
  2. 줌 글랜스: 원으로 scale 고정 → 남은 자유도=translation.
  3. 후보 영역(player odometry·parent·phase로 축소)별 다채널 점수(라벨OCR·해안edge·격자·도로) 합산.
  4. 1등이 2등을 충분한 margin으로 이기면 확정, 아니면 보류.
플레이어 아이콘 안 보이거나 미니맵 drift 클 때 재앵커 역할. 학습 불필요, 사람이 실패해석 가능. 단점: 평야·반복지형 약함, 라벨OCR 취약, 구현량 큼.
실패 + 메움
  • 다채널 합산 + 1·2등 margin + hard gate(parent·phase·odometry 범위). 낮으면 폐기·retain.
나중 (지금 아님).
· Factor graph 융합 — 위 앵커들이 생긴 뒤, 모든 관측을 확률적으로 합쳐 "좌표+신뢰도+대체후보" 출력. 최종 통합 레이어(첫 빌드 아님).
· ML 위치추론 — 보류. "줌crop+정답좌표" 데이터가 없고 합성crop은 도메인갭 남음. 위 결정론 앵커로 실제 줌crop을 auto-label해 검증 데이터가 쌓이면, 애매한 crop의 후보 ranking 보조로 재평가.
