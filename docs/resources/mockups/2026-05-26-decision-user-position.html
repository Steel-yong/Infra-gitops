유저 실시간 위치 표시 — 결정

우리 UI(Leaflet 맵)에 플레이어 자기 위치를 표시. 핵심 질문 둘: ① 어디서 뽑나(소스) · ② 학습이 필요한가(접근). 2026-05-26.

① 위치 소스 — 어느 화면에서 위치를 읽나

미니맵 실시간

플레이 중 항상 보이는 우하단 미니맵. 플레이어는 거의 중앙, 흰 화살표(방향).

  • 끊김 없는 실시간 추적
  • 방향(화살표)까지 얻음
  • 영역이 작아 호모그래피 특징점 부족 위험
  • 좌표 변환 난도 높음(좁은 영역→전체맵)

전체맵 열 때만

탭/M으로 전체맵 열었을 때 표시되는 플레이어 마커.

  • 마커 크고 또렷 → 검출 쉬움
  • 자기장 검출과 동일 좌표계 재활용
  • 맵 열 때만 = 실시간 아님
  • "실시간 표시" 요구와 안 맞음

둘 다 단계적

전체맵으로 먼저 검증 → 미니맵 실시간으로 확장.

  • 쉬운 것부터 → 리스크 분산
  • 전체맵으로 좌표 정확도 먼저 확보
  • 작업 2배, 범위 큼

② 접근 방식 — 학습이 필요한가

고전 CV 추천

PUB-39 AKAZE 호모그래피 재활용 + 화살표 아이콘 검출(템플릿/색·형태).

  • 이미 있는 자산 재활용 — sift-zone.service의 화면→게임좌표 변환
  • 학습 데이터·GPU 불필요, 즉시 시작
  • 내 화면은 방송영상과 달리 깨끗·일관 → 고전 CV 유리
  • 작은 미니맵에서 특징점 부족하면 매칭 실패 가능

ML 학습 나중

PUB-34처럼 합성 데이터 + YOLO로 플레이어 마커 검출 학습.

  • 고전 CV가 실패하는 케이스에 강건
  • 데이터 라벨링·학습·배포 = 큰 비용
  • 아직 고전 CV를 안 해봄 → 시기상조

핵심 통찰 — PUB-34와 정반대

상황입력그래서
PUB-34 (프로 위치)토너먼트 방송영상 — 지저분·가변고전 CV 2주 실패 → ML(YOLO) 전환
이번 (유저 위치)유저 본인 화면 — 깨끗·일관고전 CV로 충분할 가능성 높음 → ML은 폴백

추천

소스 = 미니맵(실시간) · 접근 = 고전 CV 먼저(호모그래피 재활용), ML은 폴백.
  • "실시간 표시"라는 요구는 미니맵만 충족함(전체맵은 열 때만).
  • 학습은 지금 필요 없음 — 고전 CV(PUB-39 호모그래피)를 먼저 시도하고, 미니맵 매칭이 불안정할 때만 ML 검토.
  • 리스크 = 미니맵이 좁아 호모그래피 특징점이 부족할 수 있음. → PoC 1건으로 먼저 검증(올려준 스크린샷에 미니맵 영역으로).

결정 후 액션

  1. Linear 이슈 생성 + 계획 3종(plan/checklist/context-notes) 작성.
  2. PoC — 미니맵 크롭 1장에 AKAZE 호모그래피 시도, inlier 수 확인(임계 통과하나).
  3. 통과 → capture에 detectPlayer() 추가(좌표+방향), shared에 PlayerPosition 타입.
