# 자기장 페이즈 1 검출 — 결정 사항 기록

## 사용자가 명시한 핵심 제약

1. **페이즈 1만 먼저 완성.** 페이즈 1이 안 되면 다른 페이즈도 무의미.
2. **자기장이 줄어드는 시점 ≠ 검출 시점.** 대기 시간(흰 원만, 외부 파란 없음)에 검출하는 게 진짜 가치.
3. **페이즈 1 줄어드는 중도 초반엔 외부 파란 안 보임** (자기장이 맵 끝에서 시작해서 파란 영역이 화면 밖). 페이즈 2~8은 줄어드는 중 외부 파란 정상.
4. **흰 원이 두 상태(대기·줄어듦) 모두에서 공통 단서.** 색 기반 검출 불가.
5. **이번 세션 자율 반복 허용.** 사용자 질문 안 함. 성공하면 종료.

## 이번 세션에서 내린 결정

### 결정 1 — 검출 알고리즘 본질 교체

이전 알고리즘: "비-파란 픽셀의 평균 좌표 + 거리 분포 90 percentile"
- 문제: 자기장 외부가 일반 맵일 때(대기 중) 동작 불가
- 문제: 노이즈에 평균이 끌림
- 결정: **흰 원 자체 검출 (Hough Circle 계열)** 로 전면 교체

### 결정 2 — OpenCV.js 의존 추가 안 함 (우선)

- 이유: WASM 초기화·Node 환경 호환성 리스크
- 대안: TypeScript로 RANSAC 또는 직접 Hough 구현
- 만약 직접 구현 다 실패하면 → OpenCV.js 시도

### 결정 3 — 분모 8160m 유지

출처: `documentation.pubg.com/en/telemetry-objects.html` (PUBG 공식 telemetry).
플레이어블 영역 816,000cm × 816,000cm.
이전 8000m → 8160m 보정 완료 후 재정정 (사용자 표 적용).

### 결정 4 — 동적 OCR 보정 측정 구간 확대

- `useOcrTimer.ts` lag 측정을 OCR 호출 → tick 시작으로 확대
- setInterval 큐잉 + 전처리 + OCR 처리 다 잡힘
- 이전 약 0.5s 측정 → 약 1.0~1.5s 실측

### 결정 5 — `useAlertTimer` 무한 루프 픽스

- 원인: page.tsx onAlert 매 렌더마다 새 함수 → useCallback dep 변동 → setState 무한
- 픽스: `useAlertTimer.ts` setDisplayState를 함수형 + 같은 값이면 prev 반환
- 외과적, 사용자 코드(page.tsx) 수정 없음

### 결정 6 — `CircleData`에 `phase?: number` 추가

- 백엔드에서 검출한 페이즈를 프론트로 전달
- TimerPanel에 "현재 페이즈: N페이즈 (검출 반경 추정값)" 표시
- 디버깅용. 진짜 페이즈는 OCR 직접 추출이 추후 작업

### 결정 7 — 검증 자동화

사진 2장(1페이즈.png, 배그 맵화면.png)을 ground truth로:
- `extractCircle(base64)` 호출 → 반경·중심 추출
- 반경: 0.24474 ±10% 안
- 중심: 사진 시각 중심과 ±5% 안
- 둘 다 통과 → PASS, 알고리즘 채택

PASS 못 하면 다른 가설로.

## 가설 우선순위

1. **A — 흰 픽셀 RANSAC** (가장 직관적, 라이브러리 0)
2. **C — 노란 점 검출** (가장 단순, 백업)
3. **B — Hough Circle 직접 구현** (정통)
4. **D — 색 전환 엣지 + RANSAC**
5. **E — Canny edge + 페이즈 한정 Hough**

## 도메인 지식 — PUBG 자기장 시각 특성

- 흰 원 둘레가 자기장 경계 (선명, 굵음, 거의 완벽한 원)
- 자기장 중심에 노란 점(다음 자기장 마커) 표시됨 — 검증용 보조
- 자기장 안에 빨간 채움 = 다음 페이즈가 작아질 예고 영역 (대기 시간에 표시)
- 격자선 매우 흐림 (확대 케이스 단서로는 약함)
- 도시명 텍스트 보임 (Map Registration 단서 가능)

## 좌표계

- `CircleData.x, y, r` = 0~1 정규화
- y는 이미지 좌표계 (위 0 → 아래 1)
- Leaflet `CRS.Simple` 변환: `[1 - y, x]` (CLAUDE.md 5부 명시)
- 정규화 분모: 맵 영역 한 변 (화면 중앙 정사각형, 1080×1080)
- 이전 코드는 화면 전체 너비/높이로 정규화 → 맵 영역 crop 후 정규화로 정정
