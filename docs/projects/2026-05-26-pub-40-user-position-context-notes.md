# PUB-40 컨텍스트 노트 — 유저 실시간 위치

## 핵심 결정과 이유

### 소스 = 미니맵 (전체맵 아님)
사용자 요구가 "**실시간** 위치 표시". 전체맵은 탭/M으로 열 때만 보여 실시간이 안 된다. 미니맵은 플레이 중 항상 보이므로 유일한 실시간 소스. 트레이드오프 — 미니맵은 작아 검출 난도가 높지만, 실시간 요구가 우선.

### 접근 = 고전 CV 먼저, ML은 폴백
"학습 시켜야 하나?"라는 질문에 대한 답. **아니오, 지금은.**
- PUB-39에서 만든 AKAZE 호모그래피(화면→게임좌표)를 그대로 재활용 가능 → 자산 재사용.
- **PUB-34와 정반대 상황**: PUB-34는 토너먼트 방송영상(지저분·가변)이라 고전 CV 2주 실패 → YOLO 전환. 이번은 유저 본인 화면(깨끗·일관)이라 고전 CV에 유리. 같은 교훈을 반대로 적용.
- ML은 데이터 라벨링·학습·배포 비용이 큼. 고전 CV를 안 해보고 ML부터 = 시기상조.

### 플레이어 ≈ 미니맵 중심
PUBG 미니맵은 플레이어를 (거의) 중앙에 두고 패닝된다. 그래서 화살표를 정밀 검출하지 않아도, **미니맵이 보여주는 맵 영역을 호모그래피로 알면 그 중심이 곧 플레이어 위치**. 화살표는 heading(방향)용. (이 가정은 PoC에서 실측 검증해야 함 — 미니맵이 완전 중앙 고정인지, 약간 오프셋인지.)

### PoC 게이트를 먼저 두는 이유
미니맵이 좁아 AKAZE inlier가 부족할 위험이 실재. 전체 구현 전에 PoC 1건으로 inlier가 임계를 넘는지 확인 → 안 되면 ML로 분기. 헛심 방지. (PUB-39 sift-zone은 줌인 "전체맵"으로 inlier 수백을 봤지만, 미니맵은 훨씬 작음 — 같은 임계가 안 통할 수 있음.)

## 재활용 자산
- `apps/services/capture/src/capture/sift-zone.service.ts` — AKAZE 호모그래피(findHomography/perspectiveTransform), 기준맵 디스크립터 사전계산.
- 프론트 마커 패턴 — `MyungdangMarkers.tsx`, `StashMarkers.tsx`, `CircleOverlay.tsx` (`[1-y, x]` 좌표 변환 포함).
- shared 좌표 규약 — `CircleData`(x,y 이미지좌표 0~1)와 동일 규약으로 `PlayerPosition` 정의.

## 좌표 변환 주의 (PUB-39과 동일)
미니맵 픽셀 → perspectiveTransform(H) → 기준맵 1200px → /1200 → 게임좌표 0~1. 프론트 Leaflet은 `[1-y, x]`. heading은 미니맵 화살표 각도 → 맵 북 기준 회전.

## 한계 / 후속
- 미니맵 중앙 고정 가정이 틀리면 오프셋 보정 필요(PoC에서 판정).
- 고전 CV 실패 시 ML(YOLO 마커 검출) — 별도 결정 목업.
