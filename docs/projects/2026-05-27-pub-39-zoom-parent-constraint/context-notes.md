# PUB-39 줌 자기장 — parentCircle 포함 제약 (컨텍스트 노트)

## 배경
- 줌인(전체맵 확대) 화면에서는 circle.service(전체맵 전제)가 실패 → SIFT-zone 폴백이 자기장을 복원해야 한다.
- PoC(.local/poc_ce.py, sift_zone_prototype) 결과: AKAZE 전체매칭 inlier가 낮아(줌 C 4~29) 호모그래피가 **불안정**. 단독으로는 허위 중심을 만든다.

## 이번 변경의 핵심 결정
- **부모 자기장(이전 페이즈 락된 원) + 페이즈 반경 고정**을 제약으로 써서 약한 호모그래피의 허위 결과를 거른다.
- PUBG 규칙: 다음 존은 항상 현재 존 **내부**. → 새 중심거리 `d ≤ 부모r − 새r + tol`.
- 제약을 순수 모듈 `zone-geometry.ts`(opencv 무관)로 분리 → 단독 유닛 테스트 가능(WASM import 회피).

## 적용 지점
- `fitCenterFixedRadius`(페이즈 알 때 중심만 RANSAC) — 부모 밖 중심 후보 즉시 기각.
- 3점 RANSAC(페이즈 모를 때) — 부모 밖 원 후보 기각.
- `capture.service` → `detectZone(base64, hintPhase, parentCircle)`로 부모 전달.

## tol = 0.05 근거
- 정규화 0~1 좌표에서 검출 오차 여유. 너무 작으면 정상 줌도 기각, 너무 크면 제약 무력화.
- 라이브 검증에서 조정 가능(아래 미해결).

## 미해결 / 라이브 검증 필요
- `SIFT_ZONE_ENABLED`는 기본 off(매 프레임 AKAZE 비용). 줌 검증 시 env로 켠다.
- 제약은 허위 결과를 **거르기만** 한다 — 호모그래피 자체 정확도는 줌 정도에 의존(과도 줌은 여전히 실패 가능).
- tol 값, MIN_STRONG_INLIERS(120)는 실제 화면공유로 튜닝 필요. → live-test 체크리스트 C 항목.

사용자 줌 테스트(`.claude/images/2v.png` 줌맵, `2vs.png` 앱) → "확대하면 인식 못함".

- `SIFT-zone 매칭 실패 (지형 특징 부족/줌 과도)` 반복 — 줌 화면 inlier가 게이트(MIN_STRONG_INLIERS=120) 미달. PoC(줌 inlier 4~29)와 일치.

### 함의 (설계 전환 필요)
- 줌 화면에서 자기장 "재검출"은 E 미니맵과 동일하게 근본 불가(특징점 부족 → 절대 로컬라이제이션 실패).
- 우리 앱은 항상 **전체 Leaflet 맵 + 락된 자기장**을 그린다 → 줌 검출이 필요 없다. **전체맵 열렸을 때 1회 락(작동) → 줌 동안 useLockedCircle이 유지(sticky)** 하면 됨.
- 따라서 SIFT 줌 폴백은 항상 실패하는 CPU 낭비 → off가 맞을 수 있음. 단 사용자가 "줌에서도 검출" 자체를 원하면 별도 접근(예: 줌 화면 흰 원 픽셀 검출 + parentCircle로 스케일 정합) 연구 필요 — 미검증.

## B안 연구 결과 (2026-05-27) — 앵커 기반 "자기장 원 = 자(ruler)" 로컬라이제이션
사용자 결정: B안 연구. 질문 "전체맵 락 상태에서 줌하면 가능?" → **가능. 그게 핵심 메커니즘.**

### 검증 (`.local/poc_zoom_ring.py`, 2v/4v/전체맵)
- 줌 화면에서 흰 자기장 원이 RANSAC 픽셀 피팅으로 깔끔히 검출됨: 2v inlier 39%, 4v 25%, 전체맵 28%.
- **지형 특징 매칭 불필요** — SIFT 실패와 무관하게 원만 보이면 됨.

### 메커니즘
1. 전체맵에서 자기장 1회 락 → 절대 중심(cx,cy)·반경 r 확보(앵커).
2. 줌 프레임에서 흰 원 픽셀 검출 → (Px,Py,Pr).
3. 스케일 s = Pr / r. (PUBG 맵 북-고정·균일 줌 → affine = 스케일+이동만.)
4. 픽셀→게임: gx = cx + (x-Px)/s, gy = cy + (y-Py)/s.
5. 안쪽 다음-페이즈 원도 픽셀 검출 → 위 변환으로 절대 좌표 → 추적.

### 남은 구현 과제 (PoC는 단일 원 검출만 검증)
- 두 원(현재=앵커 / 다음) 동시 검출·구분(반경·색).
- 검출된 원이 어느 페이즈인지 매칭(앵커 반경과 스케일 일관성).
- 부분 호(많이 줌)일 때 고정반경 중심피팅(기존 fitCenterFixedRadius 재활용 가능).
- 앵커 없을 때(전체맵 미락)는 불가 → 폴백은 유지(retain).
- 라이브 튜닝 필요.
