# PUB-39 v2 줌 자기장 (A안 — 원 ruler + 앵커) 컨텍스트 노트

## 결정 (사용자)
방법 비교(`docs/resources/mockups/2026-05-27-decision-zoom-localization.html`) 중 **A안** 채택.
A = 사용자의 "이전(앵커-링)" + "방금(페이즈 전이 역산)" 통합 = **원=배율 자(ruler) + 앵커=위치**.

## 핵심 원리
- 자기장 원은 OCR 페이즈로 반경(절대 정규화)을 아니까 **줌 배율 확정**: `scale = 검출픽셀반경 / 앵커정규화반경`.
- 위치는 **이전 전체맵 앵커**(같은 원의 절대중심)가 채움 → 픽셀↔게임 affine(스케일+이동) 복원.
- PUBG 맵 북-고정·균일 줌이라 회전 없음 → 단순 변환.

## 진행
1. **[완료] 순수 변환 모듈** `zoom-localize.ts` — `deriveZoomTransform`/`pixelToGame`/`localizeNextZone`. opencv 무관, 유닛 **8/8**.
2. [다음] 줌 화면 흰 원 **픽셀 검출**(sharp 흰픽셀 + RANSAC 원피팅 — sift-zone 기계 재사용). 현재 원(=앵커 대응) + 다음 원.
3. [다음] capture.service 배선 — 줌(전체맵 미검출) + parentCircle 존재 시 A 실행(실패하는 SIFT 대체).
4. [다음] Codex 리뷰.
5. [다음] 배포 후 **라이브 검증**(2v/4v 같은 줌). **이번엔 라이브 확인 후 머지.**

## E(유저위치)와의 관계 (정직)
- A와 E는 앵커·좌표변환 토대를 **공유**하지만 검출 대상이 다름(A=자기장 원, E=미니맵 플레이어/오도메트리).
- A 완성이 E 자동완성은 아님. 단 변환 machinery는 E에서 재사용 가능.

## 미해결
- 현재 원 vs 다음 원 구분(반경·색·OCR 페이즈로).
- 앵커 없을 때(콜드스타트) 폴백 = C(해안/edge) 또는 retain.
- 라이브 튜닝(흰 임계·RANSAC tol).

## 2단계 실데이터 검증 (2026-05-27, `.local/poc_zoom_two_rings.py`)
2v/4v 실프레임으로 검출+변환 검증.
- **2v: 성공** — 현재(흰) 원 center(1350,641) r=310 inl680. 다음(빨강) 원 center(1423,736) r66 inl819. 변환(앵커 가정) → 다음존 절대(0.567,0.623), **부모 안(중심거리 0.029 < 부모r 0.074)** = PUBG 규칙 일치. **수식+현재원 검출이 실데이터에서 작동.**
- **4v: 부분** — 현재 흰 원은 검출(center 1240,679 r103). 다음 빨강 원은 노이즈(빨강 78px만) → 실패.
- **결론**: 현재 원 로컬라이제이션(핵심)은 견고. 다음존 빨강 검출은 약함 → 튜닝 필요(빨강 임계·면적 게이트, 또는 다음존도 흰 점선이면 흰 마스크에서 2번째 원으로).
- v1 교훈 적용: 배선 전 실데이터로 먼저 검증함.

## 정정 (2026-05-27) — 빨강은 레드존(폭격), 자기장 아님
사용자 지적으로 발견: 앞의 "2v 빨강 원 = 다음 자기장"은 **오류**. 빨강 채워진 원 = **레드존(폭격 지대)**로 자기장과 무관. 그 "변환 성공"은 폭격존 좌표라 무효.
- 자기장은 **흰 원**: 큰 흰 원(현재 경계) + 안쪽 흰 원(다음). A는 흰 원만 사용.
- 흰 원 재검증(`.local/poc_zoom_two_white.py`): **큰 흰 원은 안정 검출**(2v r310 inl1036, 4v r103 inl533). **둘째 흰 원(다음)은 불안정** — 흰 글자·라벨·경로선이 가짜 원으로 잡힘(4v 화면밖 r1798 가짜).
- **다음 정밀화**: 검출된 흰 원 후보를 **알려진 페이즈 반경 비(N:N+1≈0.55)로 필터**해 현재/다음만 추출, 텍스트·라벨 노이즈 기각. 그 뒤 변환.
