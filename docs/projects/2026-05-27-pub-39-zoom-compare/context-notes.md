# PUB-39 줌 비교 — 컨텍스트 노트 (결정과 이유)

## 왜 PoC-first인가
3개를 전부 TS 제품 구현하면 2개는 버려진다(단순함 위배). 이 코드베이스는 이미 `.local/poc_*.py`로 검증→TS 이식 패턴. 사용자도 "PoC 먼저" 선택.

## PUBG 자기장 색 (육안 확인, 4v.png)
- **흰 원** = 찾을 안전구역(다음/현재 safe zone). 안쪽 lit(밝음)/바깥 dark. ← 타겟.
- **큰 파란 원** = 현재 블루존 벽(줄어드는 중). known 앵커로 쓸 후보.
- 흰 원 중심 옆에 도시명이 찍힘(4v=Mylta) → 정답 라벨로 직결.
- 미해결: phase별로 흰/파란 어느 게 "known(직전 락)"이고 어느 게 "타겟"인지. 보조 전체맵으로 확정.

## 정답(ground truth) 방법
사용자 라벨링 불필요. 줌 프레임에 도시명 보이고 erangel-cities.ts(27도시 gx,gy) 있음.
→ 흰 원 중심 = 가장 가까운 도시 = 정답 좌표. Claude 비전으로 프레임당 도시 식별해 ground_truth.json 고정.

## 1차 검출 PoC 발견 (poc_overlay_circles.py)
- 흰 RANSAC: 2v center(1350,641)r=310, 4v center(1240,678)r=103 — 흰 원(안전구역) 잘 잡음.
- 파란 RANSAC: 파란px 20만↑ → 맵 물/블루틴트 전체를 잡아 **헛원**(2v r=440 left). → 블루존 "벽 라인"만 따려면 밝은 파란 라인색·edge로 좁혀야 함. 미해결(검출 모듈 정리 항목).

## 데이터 인벤토리 (.claude/images)
- 전체맵: 1페, 2페, 2페 (1). 확대(전체맵 보임): 1페확대. 확대(부분): 2페확대, 2페확대2, 2v, 4v.
- 앱 스샷: 2vs, 4vs, io, ui맵. 참조맵: erangel_원본.jpg, assets/maps/erangel.jpg.

## 방법별 입력 의존 (중요)
- 셋 다 "직전 전체맵 락의 절대 기준"이 입력으로 필요. 정적 1장만으론 절대비교 불가 → 도시라벨로 정답·앵커 보강.
- 사용자가 짧은 공지윈도우 클립 또는 (축소+확대 같은순간) 2장 주면 실전 검증 강화(옵션, 없어도 진행).

## 자동 루프 운영
- 사용자가 /loop로 구동, 자는 동안 진행. checklist 항목 순차.
- 안전: develop/worktree 커밋만, main·push·삭제·외부망 금지.
- 막히면(애매한 정답·검출 실패) 추측 말고 노트에 기록하고 다음 항목 진행, 아침 보고.
