# PUB-39 줌 비교 — 컨텍스트 노트 (결정과 이유)

## 왜 PoC-first인가
3개를 전부 TS 제품 구현하면 2개는 버려진다(단순함 위배). 이 코드베이스는 이미 `.local/poc_*.py`로 검증→TS 이식 패턴. 사용자도 "PoC 먼저" 선택.

## PUBG 자기장 색 (육안 확인, 4v.png)
- **흰 원** = 찾을 안전구역(다음/현재 safe zone). 안쪽 lit(밝음)/바깥 dark. ← 타겟.
- **큰 파란 원** = 현재 블루존 벽(줄어드는 중). known 앵커로 쓸 후보.
- 흰 원 중심 옆에 도시명이 찍힘(4v=Mylta) → 정답 라벨로 직결.
- 미해결: phase별로 흰/파란 어느 게 "known(직전 락)"이고 어느 게 "타겟"인지. 보조 전체맵으로 확정.

## 정답(ground truth) 방법
사용자 라벨링 불필요. 줌 프레임에 도시명 보이고 erangel-cities.ts(27도시 gx,gy) 있음.
→ 흰 원 중심 = 가장 가까운 도시 = 정답 좌표. Claude 비전으로 프레임당 도시 식별해 ground_truth.json 고정.

## A1 검출 모듈 정리 — 결과와 발견 (2026-05-28, `.local/poc_detect_circles.py`)
검출기를 **색마스크 채움 RANSAC → 색분리 흰원 + 구조기반 벽** 으로 재설계. 5프레임(2v·4v·2페확대·2페확대2·1페확대) 오버레이 `.local/pub39-shots/det_*.png`.

### 핵심 발견 (이유 근거)
1. **파란 벽 라인 색 ≈ 파란 틴트 색.** 실측: 4v 벽 라인 BGR `[150,89,73]`(b-max(g,r)=65) vs 파란 틴트 배경 `[144,72,48]`(b-max=72) — 틴트가 오히려 더 파랑. → **파란 원은 색마스크로 절대 분리 불가.** 기존 `poc_overlay_circles.py`가 좌측에 1.5M px 헛원을 그린 원인이 이것. 색기반 파란 검출은 폐기.
2. **흰 픽셀은 깨끗**(프레임당 11k~30k, UI/상단 제외). 흰 안전구역 원은 흰 픽셀 RANSAC로 안정 검출.
3. **그리드선·도시라벨 흰 픽셀이 가짜 큰 원을 만든다**(저커버리지). → **각도 커버리지 게이트**(인라이어가 원주 36빈 중 ≥55% 분산)로 제거. cov<0.55 가짜 원 전부 컷.

### 해법 (현재 검출기 구성)
- 흰 원: 흰 픽셀(min(b,g,r)>175, ROI 0~0.80W·0.055~0.945H) → RANSAC(tol3, cov≥0.55, inl≥300) → Kasa 대수 재피팅. 최선 1개 + (inl≥1000 & 반지름 distinct)면 2번째.
- 파란/플레이존 벽: 색 대신 **lit/dim 경계 윤곽**(dim=b>g&b>r=파란틴트·바다, lit=그 외) → 최대 lit 컴포넌트 외곽 윤곽 → 테두리 점 제외 → RANSAC.

### 결과 (육안 + inlier)
- ✓ 흰 안전/플레이존 원 정확: 2v(inl2472,cov.72), 2페확대(inl3547,cov1.00), 2페확대2(inl3097,cov.56), 1페확대(inl3260,cov.61).
- ✓ 2페확대: 흰 원 + 벽(동심원) 동시 정확.
- △ **4v 한계**: 후반 작은 안전링(Mylta 근처)은 흰 픽셀이 적어 미검출. 검출기는 큰 원만 잡음. → 작은 원(late game)·다중 원 분리는 후속(검출 정밀화 잔여).
- 벽 윤곽법은 lit 영역이 부분일 때(2페확대)만 발화. lit이 프레임을 꽉 채우거나(1페·2페확대2) 너무 작으면(2v·4v) 미발화 — known 앵커는 보조 전체맵으로 보강하는 기존 전략 유지.
