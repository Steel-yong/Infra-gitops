## 2. LLM 영상 직접 분석 한계 vs Python 파이프라인

### 한계 (LLM 직접)

- Claude의 `Read` tool은 정적 이미지만. 영상 디코딩 못 함.
- Vision API도 마찬가지.

### 가능 (Python 파이프라인 — CPU)

- `yt-dlp` 영상 다운로드 (CPU)
- `ffmpeg` 프레임 추출 (CPU)
- 우리 `capture-service` `circle.service.ts` (Sharp + Kasa 원 피팅) → 자기장 원 검출 (CPU)
- 우리 픽셀 색상 분석 → 팀 위치 마커 추출 (CPU)
- DBSCAN 클러스터링 → 명당 자동 도출 (CPU)

CPU만으로 충분. GPU 불필요.

## 3. 프로토타입 범위 결정

전체 영상 4.7시간 처리는 큼 (예상 2~3시간 CPU). 프로토타입은 **첫 20분만**:
- 다운로드: 720p mp4 avc1 → 약 120MB → 5분 이내
- 프레임 추출: 30초 간격 → 40프레임
- 자기장 원 검출: 프레임당 ~1초 → 40초

전체 프로토타입 7분 안에 완료 예상.

## 4. PUB-33 v1과의 관계

PUB-33 v1 (mockup 격자 ±0.05) 작업:
- 워크트리 `feature/PUB-33` 보존
- 14곳 바다 좌표 자동 보정 v3 JSON 저장됨 (`/tmp/pub33/erangel_final_v3.json`)
- **시드 자체는 부정확** — 일일이 손으로 잡는 비용 vs Phase 7 자동 도출

PUB-34 결과로:
- 자기장 원 검출 ✓ → 자기장 통계 가능
- 팀 위치 마커 ✓ → 명당 클러스터링 가능
- 둘 다 잘 되면 **PUB-33 v1 폐기 + PUB-34 결과로 v2 시드 자동 생성**

## 5. 의문점 (해결 필요)

- MAP 영상에 실제 자기장이 영상 처음부터 끝까지 보이는지 (페이즈 1 wait 구간엔 자기장 없음)
- 미니맵 영역 크기 — 영상이 전체가 미니맵인지, 일부에 미니맵 + 다른 정보 함께인지
- 팀 위치 마커가 등급별로 색이 다른지, 모두 같은 색인지
- 영상 해상도별 자기장 원 검출 정확도 차이

## 6. 다음 세션 인계 사항

- 프로토타입 결과 (자기장 원 검출 정확도)에 따라 다음 분기:
  - 정확도 90%+ → 전체 영상 처리 + 클러스터링 (PUB-35 후보)
  - 정확도 낮음 → 다른 영상 시도 또는 분석 알고리즘 보정
- 사용자가 다른 MAP 영상 URL 알려주면 비교 검증 가능
