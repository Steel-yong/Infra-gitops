# 포스트모템 — 새벽 자율작업 반복 실패 (WSL 네트워크 단절)

> **3회 반복된 사고.** 증상만 때우고 원인분석을 안 해서 같은 실패가 되풀이됐다. 이 문서가 그 원인분석이고, 재발 방지 기록이다.

## 사고 요약
- 증상: 새벽 자율작업(tmux `pubg`, `claude /loop`)이 **아무것도 못 하고 멈춤**. 여러 밤 반복.
- 직접 관측: Claude API `ConnectionRefused`/소켓 닫힘 → 세션 idle. 마지막 정상작업 2026-05-28 00:24, 이후 ~7.8h 정지.

## 근본 원인 (5 Whys)
1. 왜 멈췄나? → WSL이 Anthropic API에 못 닿음.
2. 왜 못 닿나? → **WSL 인터넷 전체 단절**(ping 8.8.8.8 100% 손실 — API만이 아님).
3. 왜 전체 단절? → WSL이 **모든 트래픽을 Tailscale exit node(집 데스크탑 `home-desktop`)로 라우팅**하는데 그게 오프라인.
4. 왜 exit node 오프라인이 전체를 죽이나? → **split routing/폴백 없이 "전부 집 PC 경유"로 설정.** 집 PC를 끄면(끄라고 안내함) WSL 인터넷이 통째로 죽음.
5. 왜 이게 **반복**됐나? → **첫 실패 후 원인분석·문서화를 안 함.** 같은 취약 설정을 그대로 재사용 + "된다"고 재확인 → 또 실패. ← **메타 근본원인: RCA 부재로 인한 재발.**

## 진짜 원인 정리
- 기술: 집 IP는 **YouTube 다운로드에만** 필요한데, **모든 WSL 트래픽을 exit node로** 보내는 전역 설정이라 단일 장애점이 됨.
- 프로세스: **실패 후 원인분석을 안 하고 "된다"고 단정** → 동일 실패 반복. (CLAUDE.md "원인 파악 전 흔한 수정 금지" 위반.)

## 영구 수정
1. **exit node 상시 사용 금지.** WSL 기본 = 직접 인터넷. (2026-05-28 `tailscale set --exit-node=`로 해제, 검증: ping 0% 손실 / api.anthropic.com 도달.)
2. **집 IP는 다운로드 한정**: yt-dlp `--proxy socks5://<home-tailscale-ip>:port` 또는 집 머신에서 직접 실행. 집 PC 꺼져도 다운로드만 실패, WSL·API는 무사.
3. **자율/장시간 작업 사전 점검(프리플라이트) 의무화** — 아래 게이트.

## 재발 방지 게이트 (자율 런·"꺼도 됨" 안내 전 반드시)
- [ ] `ping -c1 8.8.8.8` 성공? `curl api.anthropic.com` 도달?
- [ ] 작업이 외부 단일 장애점(특정 PC·exit node·홈 네트워크)에 의존하나? 의존하면 그 의존을 제거하거나 명시.
- [ ] "컴퓨터 꺼도 된다"는 **의존 없음을 검증한 뒤에만** 말한다. 검증 없이 단정 금지.
- [ ] 실패 발생 시 **재시도 전 원인분석부터.** 증상 때움 금지.
