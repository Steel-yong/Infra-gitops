# capture-service 스케일링 (추후 해결 과제)

> 현재 구조: 사용자 1명당 **0.5초마다 1장(2장/초)** 전송 × **2~3초/장 처리** + busy 가드 없음.
> → 1인당 초당 4~6 CPU-초 요구. **다중 사용자엔 그대로 N배 부담** → 스케일 안 됨.
> 우선순위: **1명 기준 동작(줌 로컬라이제이션 등) 확보 후** 해결. 인프라(K8s/ArgoCD) 보유.

## 해결안 (우선순위순)
1. **busy 가드(skip-to-latest)** — 처리 중이면 들어온 프레임 버리고 최신 한 장만 처리. 1인당 부하를 "2~3초당 1장"으로 캡. **저비용 큰 효과, 사실상 지금도 넣는 게 맞음(밀림·중복 처리 방지).**
2. **전송률↓ / 클라 게이트** — 2장/초 → 1장/초, 또는 클라가 싸게 "맵 열림" 추정해 관련 프레임만 전송.
3. **검출 클라사이드 이동** — opencv.js/Canvas로 브라우저에서 검출(OCR은 이미 tesseract.js로 클라). **백엔드 병목 제거 → 사용자 수만큼 자동 분산. 스케일 최선책.**
4. **검출 속도 최적화 + 수평확장** — 해상도↓·SIFT 제거로 2~3초 단축, K8s capture 레플리카 증설.

## 메모
- 게임플레이 중 전체맵 미표시 프레임은 맵영역 검출에서 빨리 빠져 무거운 추출은 스킵(부하 일부 완화). 단 맵영역 검출 자체는 매 장 돎.
- 2026-05-27 사용자 지적으로 기록. 줌 기능 1명 동작 확정 후 착수.
