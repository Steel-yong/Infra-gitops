다음 작업 (사용자 결정)

  1. 실제 게임 페이즈 1 실측 검증 — 도커 capture 재빌드 완료. 게임에서 페이즈 1 자기장이 우리 지도와 일치하는지 확인.
  2. 페이즈 2~9 tracking — 이전 자기장 mask + 페이즈 N 반경 후보 (페이즈 1 알고리즘과 본질 동일)
  3. 페이즈 9 특수 처리 — 거의 점 (반경 < 0.05m). 노란 점 + last known 락
  4. 확대 케이스 대응 — Map Registration (격자선 + 도시명 + ORB)

한계 (정직하게)

  • 이 알고리즘은 노란 점 마커가 화면에 있어야 동작. PUBG는 자기장이 표시될 때 항상 마커도 같이 표시하므로 일반적으론 안전.
  • 노란 점이 가려진 케이스(예: 다른 UI 오버레이) → 흰 픽셀 RANSAC fallback으로 자동 전환. RANSAC도 ±10% 안에서 동작.
  • 사진 2(배그 맵화면)는 페이즈 1 반경에 가깝게 검출됨. 만약 다른 페이즈 자기장이었다면 페이즈 1 강제 적용은 부정확할 수 있음 → 페이즈 2+ tracking 작업에서 일반화 필요.
