PUB-30 진행 보고서

2026-05-14 · OCR 타이머 + 자기장 검출 기능 — 완료/미완료/현재 설정 정리

1. 완료된 작업

📺 화면공유 + 캡처 파이프라인

  • 화면공유 안내 문구 제거 (사용자 요청)
  • video element → 1초 간격 캡처 → OCR/자기장 검출 처리

⏱ OCR 타이머 (Tesseract.js)

  • 크롭 영역 비율 기반 (해상도 자동 대응): x:0.83, y:0.67, w:0.17, h:0.08
  • OCR 전처리: 3배 확대 + 순수 흰색 필터(R/G/B>220만 검정으로) → 인식률 향상
  • 한 번 OCR로 "락" → 로컬 카운트다운 → 5초마다 OCR 보정
  • OCR 처리 지연 2.5초 보정 → 웹 타이머 ≈ 인게임 타이머
  • 파서: /(\d+):(\d{2})/ 패턴 텍스트 어디서든 매칭 (페이즈 숫자 섞여 있어도 OK)
  • video 해상도 + 크롭 영역 + 인식 결과 모두 콘솔 로깅

🚨 빨간 느낌표 (줄어드는 중) 감지

  • 크롭 영역 안쪽 좌측 20%에서 빨간 픽셀 비율 측정 (R>150, G/B<100, 비율>2%)
  • 감지되면 OCR 자체 스킵 → 잘못된 "!" → "1" 인식 방지
  • 줄어드는 중에는 알람 안 보냄 (이미 늦은 시점)
  • 상태 라벨 동적 변경:
    • 대기 중: "이동까지 남은시간"
    • 줄어드는 중: "자기장이 줄어들고 있습니다."

🔔 알람 시스템

  • 비프음 자체 생성 (Web Audio API, 880Hz × 4회 × 1.8초)
  • Web Notifications API 알림 동시 발송
  • 대기 중에만 발송, 줄어드는 중에는 안 보냄
  • 발송 조건: 잔여 초가 사용자 설정 임계값(30/20/10)에 도달

🎯 자기장 검출 (capture-service)

  • 파란 자기장 외부 + 비-파란 자기장 내부 픽셀 기반 검출
  • 내부 픽셀 trimmed mean으로 중심 추정 (outlier 강함)
  • 거리 90 percentile로 대략 반경 → PUBG 9개 페이즈 반경에 자동 스냅
  • 페이즈 1 → 0.1875, 페이즈 2 → 0.1375, ... 페이즈 8 → 0.0044

🔒 자기장 원 위치 락 (useLockedCircle)

  • 줄어듦→대기 전환 시점에만 새 위치 검출 후 락
  • 대기 중 + 줄어드는 중 동안 위치 고정 (jittering 해결)
  • 다음 페이즈 시작 시 자동 갱신
  • 위치 추천도 락된 원 기준으로 동작

📍 비밀창고 마커

  • 에란겔 15개 비밀창고 좌표 픽셀 추출 + DB 시드
  • 원본 에란겔 이미지(빨간 동그라미 없는) 사용
  • 펄싱 골드 마커 + 호버 시 "💰 비밀창고" 툴팁
  • 태이고 비밀창고 14개도 정상 표시

2. 현재 설정값

OCR 관련

// useOcrTimer.ts OCR_REVERIFY_SECONDS = 5 // 락 후 N초마다 OCR 재검증 OCR_DRIFT_TOLERANCE = 3 // 로컬 추정 vs OCR 차이가 N초 초과 시 재동기화 OCR_LAG_COMPENSATION_SECONDS = 2.5 // 락할 때 OCR 값에서 차감 (게임 sync) // page.tsx CAPTURE_LAG_LEAD_SECONDS = 0 // 알람 lead — 0 (정확한 시점)

OCR 크롭 영역

// timer-ocr-utils.ts (비율 기반 — 해상도 자동 대응) TIMER_REGION_RATIO = { x: 0.83, // 화면 가로 83% 지점부터 y: 0.67, // 화면 세로 67% 지점부터 w: 0.17, // 가로 17% 폭 (우측 끝 1.0까지) h: 0.08 // 세로 8% 높이 }

자기장 페이즈 반경 (capture-service)

PUBG_PHASE_RADII = [ 0.1875, // phase 1: 1500m 0.1375, // phase 2: 1100m 0.0825, // phase 3: 660m 0.05, // phase 4: 400m 0.03, // phase 5: 240m 0.0181, // phase 6: 145m 0.00875, // phase 7: 70m 0.0044 // phase 8: 35m ]

4. 아직 못한 / 보완할 작업

🔧 OCR 페이즈 번호 직접 추출

  • 현재: capture-service가 검출 반경 → 9개 페이즈 반경 중 가장 가까운 값에 자동 스냅
  • 한계: 검출이 부정확하면 잘못된 페이즈로 매핑됨
  • 개선안: OCR이 읽는 영역에 "페이즈 N"이 포함되어 있으므로 숫자 추출
  • 현재 파서는 "M:SS"만 추출 — 페이즈 숫자도 같이 파싱하면 정확도 보장

🔧 인게임 타이머 sync 정밀 검증

  • 현재 OCR_LAG_COMPENSATION_SECONDS = 2.5 (실측 기반)
  • 사용자 머신 성능/네트워크에 따라 lag 달라질 수 있음
  • 이상적: lag을 자동 측정 (OCR 시작~완료 시간 측정)

🔧 자기장 검출 정확도 — 페이즈 후반 검증

  • 페이즈 1~2는 큰 원이라 검출 잘 됨 확인 필요
  • 페이즈 5~8 (매우 작은 원) 시 정확히 감지되는지 검증 필요
  • 맵 종류별 (에란겔/태이고) 색상 차이로 임계값 조정 필요할 수도

🔧 알람 사운드 옵션

  • 현재: 단일 비프음 (880Hz × 4회)
  • 제안: 30/20/10초 별로 다른 톤 (사용자 식별 가능)
  • 제안: 사용자가 사운드 ON/OFF 선택
  • 제안: 사운드 볼륨 조절

🔧 테스트 코드 업데이트

  • useOcrTimer 테스트가 새 로직 (락, 보정, 빨간 느낌표 우선)을 반영 안 함
  • useAlertTimer 테스트가 새 leadSeconds + isShrinking 반전 로직 반영 안 함
  • useLockedCircle 테스트 없음
  • 커버리지 95% 목표 미달 가능성

🔧 알람 권한 UX

  • 현재 사용자가 수동으로 "알림 권한 허용" 버튼 클릭해야 함
  • 비프음은 권한 없어도 동작하지만 브라우저 알림 보려면 권한 필요
  • 처음 공유 시작 시 자동 권한 요청 추가 가능
